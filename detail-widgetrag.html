WidgetRAG — B2B SaaS RAG 상품 추천 챗봇

2026.06.19 – 07.10 (약 3주, 6단계) · 팀 2명 (이윤화·홍채원) · 백엔드 / RAG 파이프라인 / 크롤링
쇼핑몰마다 상담 인력 없이 실시간 상품 문의에 대응하기 어렵고, 범용 챗봇은 실제 상품 데이터를 반영하지 못해 엉뚱한 답변(환각)을 내는 문제에서 출발했습니다.
Overview

프로젝트 개요

상품 CSV 업로드만으로 상품 DB를 학습한 RAG 챗봇을 자동 생성하고, 검색된 상품 목록 안에서만 답변하도록 설계해 환각을 최소화한 것이 핵심 차별점입니다.

widget.js 한 줄 삽입으로 쇼핑몰에 즉시 설치되며, 66girls(~1,671건)·Daiso(~10,477건) 두 쇼핑몰을 하나의 엔진으로 동시 운영했습니다.

Architecture

아키텍처

관리자 웹(Biz Admin) · 쇼핑몰 위젯(66girls·Daiso) │ widget.js 한 줄 삽입 (REST/HTTP) ▼ Spring Boot 백엔드 (인증 · 상품 · RAG 오케스트레이션) │ ├─ PostgreSQL (company · member · product, companyId FK 격리) └─ OpenSearch (client_code 필터 · kNN, HNSW) │ ▼ Python AI 서버 (FastAPI · bge-m3 · Gemma/EXAONE, 로컬 GPU) RAG 파이프라인(8단계): ① CSV 업로드→청킹 ② GPU 임베딩(bge-m3) ③ OpenSearch 색인(client_code 격리) ④ 질문 벡터화 ⑤ 필터+top-k 검색(k=3) ⑥ 프롬프트 구성 ⑦ Gemma 응답 생성 ⑧ 응답 · Fallback(실패 시 목업 대체)

모든 테이블이 companyId(FK)로 연결되어 client_code 기준으로 논리적으로 완전히 격리됩니다. WSL 폴더 물리 격리, OpenSearch client_code 필터, PostgreSQL companyId(FK) 논리 격리로 멀티테넌시를 검증했습니다. 검색 결과 0건이거나 GPU 응답 지연·연결 실패 시에는 목업 응답으로 대체해, 실제 상품 없이 LLM이 지어내는 것을 원천 차단합니다.

Problem Solving

문제 해결 과정

업로드 파이프라인 병목 — 처리 시간 34분

문제
대량 상품 데이터를 업로드할 때 전체 처리 시간이 과도하게 길었습니다 (daiso ~10,477건 기준 약 34분).
원인
임베딩 생성과 OpenSearch 색인 단계가 전체 처리시간의 95.8%를 차지하는 병목 구간으로 확인됐습니다.
해결
업로드 파일을 청크 단위로 분할해 임베딩 요청을 병렬 처리하도록 파이프라인을 재설계했습니다.
결과
동일 데이터셋 기준 총 처리시간을 34분에서 16분으로 약 52% 단축했습니다. 남은 과제는 대량 업로드 시 GPU 리소스 모니터링 체계 구축입니다.

기타 트러블슈팅

문제
OpenSearch 문서 생성 시 Map.of()에 null 값이 포함되면 예외가 발생했고, 127.0.0.1/localhost 혼용 시 Origin 차이로 세션 쿠키 공유가 실패했으며, 정적 리소스 변경이 실제 서빙에 반영되지 않는 문제가 있었습니다.
해결
null을 허용하는 HashMap으로 교체하고, Base URL 오리진을 통일했으며, target/classes/static이 실제 서빙 경로임을 확인해 mvn clean spring-boot:run 재빌드를 규칙화했습니다.
결과
실데이터 검증 과정에서 CSV BOM, 중복 상품ID, 영문+숫자 혼합ID 등 노이즈 패턴을 조기에 발견해 파싱·정제 로직을 사전 보강했습니다.

Learnings

배운 점

멀티테넌시 격리 아키텍처를 처음부터 설계한 경험을 얻었고, RAG·로컬 LLM 연동 파이프라인을 Spring Boot·FastAPI 서버 분리 구조로 직접 구축했습니다. 병목 구간을 수치로 확인하고 근거 기반으로 최적화하는 과정에서 성능 개선은 감이 아니라 측정에서 시작된다는 점을 체감했습니다. 이후 클라우드 인프라 전환(Docker Compose + AWS EC2 + CI/CD), AI 서빙 최적화(양자화), 품질보증 자동화를 다음 단계로 계획하고 있습니다.
